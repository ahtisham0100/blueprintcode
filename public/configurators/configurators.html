SHEET 01 — TOOL TYPES

Six shapes, mixed to fit the sale.

Most businesses need two or three of these, not all six. Which ones depends entirely on where your customers currently get stuck — and that's usually obvious from the questions your sales team answers most often.

SHEET 02 — THE CONNECTED SYSTEM

The tools are the easy part. Connecting them isn't.

Five separate tools that each ask the same six questions is five abandoned sessions. The architectural decision that makes the difference is storing the customer's answers once, in a shared profile, and letting every tool read from it.

Each tool stays short. Collectively they behave like one system that remembers you.

A room measured in the planner is still measured when the customer reaches the screen finder an hour later.

SHEET 03 — UNDER THE SURFACE

Where these projects usually fail.

Rarely on the rendering. Almost always on the commercial rules — the combinations that can't be built, the discount that applies differently than anyone wrote down, the configuration that reaches the warehouse in a form nobody can pick.

One real example: a volume discount that counts units rather than distinct products. Trivial to state, easy to implement backwards, and wrong in a way that only shows up in the margin report months later.

CUSTOMER-FACING
  • Responsive guided journeys, built mobile-first
  • Live visual feedback as options change
  • Alternatives offered when something won't work
  • Save, share and return to a configuration
  • One readable summary at the end
COMMERCE ARCHITECTURE
  • Pricing authority on the server, never in the browser
  • Product and compatibility rules held as data, not code
  • WooCommerce, Shopify or API hand-off to checkout
  • Configurations that reach fulfilment in a pickable form
  • Structured so an AI advisory layer can be added later
