## 1. What this project is

`blueprintcode.ai` — a Next.js 16.3.4 (App Router, Turbopack) marketing site on
Vercel, with a Payload CMS 3.90.2 admin being built alongside the old `/admin`.
DNS is at GoDaddy, hosting on Vercel, database on Neon Postgres, media on
Cloudflare R2, email via Resend (not wired yet).

Three hosts, one Next app, split by `src/proxy.ts` and `next.config.ts`:

| Host | What | Notes |
|---|---|---|
| `blueprintcode.ai` | public site | `/cms` and `/api/cms` are 404 here |
| `admin.blueprintcode.ai` | Payload admin at `/cms`, API at `/api/cms` | everything else 301s to the main site; noindex |
| `media.blueprintcode.ai` | files from R2 via the `/media/[...key]` route | Vercel domain, host-rewritten in next.config |

Locally (one dev server, port 5000): **`http://localhost:5000` is the ADMIN host**
(`/cms`) because Google OAuth only accepts `http://localhost` as a redirect;
**the public site is `http://127.0.0.1:5000`**. Media is `http://localhost:5000/media/...`.

## 4. Conventions (follow these exactly)

- **Tests first.** Every pure module gets a `*.test.ts` beside it (Vitest, node env, `npm test`). Keep logic pure and inject I/O (see `serve.ts`, `handlers.ts`, `hooks.ts`). Current suite: 35 files / 204 tests, all green; keep it that way.
- **Type-check** with `npx tsc --noEmit -p tsconfig.json` (ignore errors under `.next/` only if they are stale; a build regenerates them).
- **Build** with `npm run build` before committing anything that touches routing/config. Prebuild runs chrome injection + db-guard + `payload migrate`.
- **Schema changes = migrations.** `npm run migrate:create <name>` → review the file → `npm run migrate` (applies to the dev branch). Never rely on dev push (`push: false`). If Payload ever prompts about "dev mode … data loss", the dev DB was pushed: drop schema `cms`, `npm run migrate`, `npm run seed:admins`.
- **After collection changes:** `npm run generate:types` and commit `src/payload-types.ts`. The dev server regenerates `src/app/(cms)/cms/importMap.js` when you reference new components — commit it too.
- **Restart the dev server** after changing collection configs/hooks/strategies (Payload caches its instance; hot reload is not enough). Use the `bpcode-dev` launch config (`preview_start`), never `npm run dev` in a shell.
- **Commits:** small, one concern each, message explains why, end with the attribution line the session's system reminder specifies. `git fetch` + rebase before push — the old `/admin` uploader commits demo files to `main` from production. Never commit the 22 `public/*.html` files that `prebuild` stamps in the working tree.
- **Never touch production data from local.** `.env.local` points at the Neon `development` branch and the `cms-local-testing-bucket`; `db-guard` enforces it. `ALLOW_PROD_DB=1` only for a deliberate, user-approved one-off.
- **Public exposure of anything CMS-driven goes behind a flag** (`isCmsPublic()` for demos; `BLOG_PUBLIC` for the blog, see §8) until the user launches it.
- **Pasted/raw HTML must never run on the admin origin.** That is why previews are served on the public host with a signed token.
- **Blueprint theme:** admin styling lives in `src/app/(cms)/custom.css` via Payload CSS variables (navy `#0B1A2E`, ink `#EAF1F8`, Bebas Neue titles, DM Mono labels, IBM Plex body, 2px radii). New admin components use the existing `.bpc-*` patterns.

## 6. Testing the admin without Google (local)

Mint a session for user id 1 and use it as the `bpc-token` cookie:
```bash
node --env-file=.env.local --input-type=module -e "
import { SignJWT } from 'jose'; const now=Math.floor(Date.now()/1000);
process.stdout.write(await new SignJWT({ email:'james@blueprintcode.ai' }).setProtectedHeader({alg:'HS256',typ:'JWT'}).setSubject('1').setIssuer('bpc-cms').setAudience('bpc-cms-session').setIssuedAt(now).setExpirationTime(now+8*3600).sign(new TextEncoder().encode(process.env.PAYLOAD_SECRET)));"
```
- curl: `-H "Cookie: bpc-token=<token>"` against `http://localhost:5000/api/cms/...`
- browser pane: from a `/cms/login` page run `document.cookie='bpc-token=<token>; path=/; SameSite=Lax'` — **always with `path=/`** (a cookie without it lands on `/cms` and shadows the real one).
- REST cheat sheet: `POST /api/cms/<collection>?draft=true` (draft), `PATCH /api/cms/<c>/<id>` with `{"_status":"published"}` (publish) or `{"_status":"draft"}` (unpublish — a plain update; `?draft=true` only saves a draft version and does NOT unpublish), `DELETE /api/cms/<c>/<id>`.
- Client uploads: `POST /api/cms/storage-s3-generate-signed-url` → `PUT` to the URL → `POST /api/cms/media` multipart with `_payload` + `file` JSON (see `src/cms/media/gallery.ts`).

## 7. Known gotchas (each cost real time)

- Payload's CLI needs `"type": "module"` in package.json; `payload run script.ts` executes the file (make it self-run) and drops extra argv (use env vars).
- `payload.secret` is a sha256-derived value; sessions sign/verify with the RAW `PAYLOAD_SECRET` via `sessionSecret()` — never mix.
- Underscore-prefixed folders under `app/` are private (unroutable). Route handlers' `notFound()` renders only the bare 404; the demo route fetches `/not-found-page` instead, with a loop guard.
- `req.url` in route handlers normalises to `localhost` in dev → use `PUBLIC_SITE_URL`/`SITE_URL` for self-fetches.
- The `afterFiles` static-demo rewrite runs BEFORE dynamic routes; it is generated from `public/*/index.html` so only real static demos are rewritten.
- The storage plugin stores browser uploads under the browser's filename in a `media/<uuid>/` folder; `hooks.ts` moves them to the immutable name after save. Admin thumbnails must include that folder.
- `payload migrate` output is verbose; the `add_*` migration for a new collection must be reviewed (the first one needed `CREATE SCHEMA`).
- Google Cloud OAuth "Internal" requires the project to live under the Workspace org.

## 8. Phase 5 — Blog: what to build

Single writer (admin or writer role), Word-style editing, SEO-first, ISR. The blog has no static predecessor, so it
can launch independently of the demos flag: add a `BLOG_PUBLIC` flag (same shape as `isCmsPublic`, in `src/lib/flags.ts`)
and gate every public blog route and sitemap/feed entry on it.

### Collections (in `src/cms/collections/`, `admin.group: 'Content'`)
1. **Posts** (`posts`)
   - Content tab: `title` (req), `slug` (req, unique, validated like demos — reuse the slug rules with a blog reserved list: `feed.xml`, `category`, `page`; auto from title), `excerpt` (textarea, ≤ 200), `cover` (upload → media), `body` (richText, Lexical — headings h2–h4, lists, quotes, links, inline code, code block, tables, **upload/image blocks from Media**, a `Callout` block, a `CTA` block, a `DemoEmbed` block referencing a demo slug rendered as an iframe), `category` (relationship → categories), `author` (relationship → authors), `publishedAt` (date, defaults now on publish), `readingTime` (number, computed in a beforeChange hook from the body — pure helper + test).
   - SEO tab: reuse the same `seo` group shape as Demos (`metaTitle`, `description`, `canonical`, `noindex`, `ogTitle`, `ogDescription`, `ogImage`, `jsonLd`) and the `SeoPreview` component (make its URL prefix configurable: `/blog/<slug>`).
   - Access: create/update by admin **or writer**; delete admin only; read: published public, drafts for logged-in users. Versions: drafts + autosave + schedulePublish, like Demos.
   - Hooks: revalidate `/blog`, `/blog/<slug>`, `/blog/category/<cat>`, `/sitemap.xml`, `/blog/feed.xml` on publish/unpublish/rename (pure planner like `demos/revalidate.ts` + tests); IndexNow ping in production (reuse `scripts/lib/indexnow.mjs`); redirect row on slug rename (reuse `redirectForSlugChange`, from `/blog/old` to `/blog/new`).
   - `admin.preview`: `${PUBLIC_SITE_URL}/blog-preview/<id>?token=…` using `demos/preview.ts` generalised (audience per collection) — previews on the public host, never the admin host.
2. **Categories** (`categories`): `name`, `slug`, `description`. Admin + writer.
3. **Authors** (`authors`): `name`, `slug`, `bio` (textarea), `avatar` (media), `title`, links. Admin + writer.

Migration: `npm run migrate:create add_blog` → review → `npm run migrate`. Regenerate types.

### Public site (`src/app/(site)/blog/...`)
- `/blog` — index (paginated, 12 per page, newest first), category filter links, cards with cover/thumbnail, excerpt, date, reading time. Static + ISR (`generateStaticParams` for pages; long `revalidate`, revalidated by hooks).
- `/blog/[slug]` — the post: Lexical → React (use `@payloadcms/richtext-lexical`'s converters), cover, author box, category, date, reading time, prev/next, share links; the site header/footer via the normal `(site)` layout (posts are React pages, NOT raw HTML like demos).
- `/blog/category/[slug]` — filtered index.
- `/blog/feed.xml` — RSS 2.0 (route handler).
- `generateMetadata` per page: title, description, canonical, OG/Twitter (image from cover/ogImage), noindex when set; `BlogPosting` + `BreadcrumbList` JSON-LD on posts (extend `src/lib/seo.ts`).
- Sitemap: add post/category URLs (pure helper + test, mirroring `demos/sitemap.ts`); gate on `BLOG_PUBLIC`.
- `/blog-preview/[id]?token=` route for drafts (public host, signed, noindex, no-store).
- `blog` and `blog-preview` are already reserved demo slugs.
- Insights migration: the existing `/insights` notes (`src/app/(site)/(content)/insights/notes.tsx`) should become posts — write `scripts/import-insights.ts` (payload run) that creates them as drafts with their dates; add Redirect rows `/insights/<slug>` → `/blog/<slug>` **only at switch-over** (do not break `/insights` now). Sitemap keeps `/insights` until then.
- Design: match the site's blueprint aesthetic (see `(content)` pages' CSS conventions: Bebas Neue display, DM Mono labels, sheet/drafting-grid motifs). Mobile-first, 16px gutters.

### Admin UI
- Posts list: default columns title, category, status, publishedAt; Preview action in the edit header (mirror Demos).
- Writer role: verify a writer can create/edit posts and media but sees no Demos/Redirects/Users.
- Dashboard: add Posts stats + recent posts panel (extend `Dashboard.tsx`).

### Tests to write (minimum)
- pure: post slug validation, reading-time calc, revalidation planner, sitemap entries, RSS builder (docs → escaped XML), Lexical→React/HTML render for each block type, JSON-LD builders, preview token audience separation, insights import planner.
- collections: fields present per tab, access matrix (admin/writer/anon), hooks call the planner + IndexNow only in production.
- routes: `blog-preview` token rules (403/404/200 + headers); feed route content-type; blog index/pagination helper.
- config: `BLOG_PUBLIC` flag semantics; reserved slugs updated.
- End-to-end (manual, curl/browser as in §6): create draft → not public → publish → `/blog/<slug>` 200 with correct head tags → appears on `/blog`, category page, sitemap, feed → rename → old URL 308 → unpublish → 404 (custom page). Run `npm run build`. Verify in the browser pane at 1280×900, then reset the viewport.
